## Исправлено: точность хеша команды

В `internal/admincommand/types.go`, функции `normalize`, промежуточное
декодирование JSON в `any` преобразовывало числа в `float64`.
`9007199254740992` и `9007199254740993` давали одинаковое каноническое
значение. При этом прикладная структура принимала исходный `int64`.
Нарушался инвариант: другой payload с тем же ключом должен давать конфликт,
а не квитанцию предыдущего запроса.

Исправление использует `json.Decoder.UseNumber()`. Сортировка свойств
и независимость от пробелов сохраняются. Добавлены проверки точности
на границе 2^53, около MaxInt64 и эквивалентности разных порядков полей.
Ошибки преобразования не игнорируются.

Существующие хеши не переписываются: повтор старой команды с большим
числом может получить конфликт. Нельзя обходить такой конфликт слепой
повторной отправкой с новым ключом; сначала проверить объект и квитанцию.
Обычные положительные целые в точном диапазоне сохраняют хеш.

## Исправлено: атомарность административного lead-status

Дополнительное чтение подтвердило, что `ConfigureAdmin` открывал и
фиксировал отдельную pool-транзакцию, хотя `Store.Execute` уже держал
транзакцию квитанции и domain savepoint. Отказ записи квитанции мог
оставить правило, job и native audit независимо зафиксированными.

Добавлен `RuleStore.ConfigureAdminTx`. Он использует переданный `pgx.Tx`
для авторизации, CAS правила, job receipt и native audit, не выполняя
самостоятельный commit. `admincommand.applyLeadStatus` передаёт текущий
`domainTx`. Существующий `ConfigureAdmin` остаётся обёрткой с собственной
транзакцией для самостоятельных вызовов. Widget worker-путь не менялся.

Регрессия `TestLeadStatusMutationRollsBackWhenAdminReceiptAuditFails`
принудительно ломает запись outer receipt audit после успешного domain
savepoint. Проверяются отсутствие правила, job, configuration receipt,
admin audit и admin receipt, затем успешное выполнение тем же ключом
после снятия сбоя и единственный эффект межпользовательского replay.

Новых миграций, маршрутов или разрешений ролей нет.

## Открытый риск: внешний эффект Activity и квитанция

`Store.Execute` по-прежнему держит транзакцию и savepoint при вызовах
`applyActivity`: `AdminConfigure`, `AdminCreatePanel`, `AdminPatchPanel`
и `AdminRotateShare`. Откат Core не откатывает внешний эффект Activity.
Исправление локального SQL lead-status не закрывает распределённый путь.

Перенос внешних вызовов здесь не выполнен. Нужны durable intent до
 dispatch, тот же command ID на стороне владельца, восстановление исхода
чтением и fault-injection между внешним эффектом и commit квитанции.
Для patch панели отдельно требуется командная идемпотентность, не только
CAS. Перенос вызовов за Commit без восстановления не является решением.

библиотеки Go вне репозитория. Затем проектные проверки действительно
