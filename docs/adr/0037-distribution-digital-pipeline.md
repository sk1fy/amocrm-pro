# ADR-0037: вход Digital Pipeline и ключи группы

## Контекст

Тестовое развёртывание добавило распределение при входе сделки на этап
amoCRM. Изменения были проверены на сервере и перенесены в Git из аудита
06.10.2026. Обычный webhook и DP могут доставляться в разном порядке.

## Решение

Core принимает JSON и form-urlencoded DP, проверяет scope установки,
аккаунта и группы и сохраняет событие до подтверждения приёма.
Миграция 000022 добавляет durable DP inbox/trigger. Время исходного события
передаётся TeamOS без подстановки текущего времени при отсутствии факта.

Миграция 000023 хранит ограниченные DP credentials: хеш и шифротекст,
scope установки/аккаунта/группы/ревизии binding. Выдача идемпотентна через
подписанный приватный мост. Ключ не заменяет обычный webhook key и не
авторизует runtime. Legacy DP key остаётся совместимым.

Widget bootstrap/permissions и runtime-чтения полностью проверяют JWT,
но не расходуют jti. Runtime write=true расходует jti и сохраняет replay
protection; повреждённое тело обрабатывается fail-closed. Таймаут чтения
сделки увеличен для полного вызова TeamOS.

## Отклонённые варианты

Ручной выбор общего webhook key раскрывает лишнюю конфигурацию и может
связать триггер с другой интеграцией. Расход jti на каждое чтение мешает
повторным чтениям SDK. Подстановка now вместо времени источника скрывает
неопределённость и меняет порядок событий.

## Последствия

Core и TeamOS обновляются согласованно. При rollback существующие
credentials и ключи шифрования сохраняются; down миграций уничтожает
данные и не применяется к staging при переносе исходников. Диагностика
возвращает только безопасные счётчики, без ключей и payload.
