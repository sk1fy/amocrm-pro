# 0050. Контакт активации и сделка по эпизоду установки

## Контекст

В кабинете видно, какой виджет установлен и с кем связаться. Автоматическая
сделка ведётся в отдельном аккаунте компании.

## Решение

Core получает проверенный контекст виджета, читает профиль сотрудника
amoCRM и передаёт Platform данные через существующую mTLS-идентичность.
Platform блокирует курсор установки и сверяет аккаунт, интеграцию,
поколение и последовательность авторизации. Контакт сохраняется
у подтверждённого текущего эпизода. Повторная отправка сохраняет первый
подтверждённый контакт.

Первая подтверждённая установка виджета в аккаунте ставит задачу сделки.
Переустановка и повторная авторизация сохраняются в истории установки.
Контакт может приблизить её выполнение. Обработчик берёт воронку и этап
из действующего сопоставления с аккаунтом компании. Core пишет через
учётные данные отдельной приватной интеграции, связанные с конкретным
аккаунтом и DNS-именем.

Перед запросом создания Platform сохраняет идентификатор эпизода в
названии сделки. После неоднозначного ответа повтор только ищет точное
название. После явного отказа новая попытка разрешена. Возврат задачи
из terminal-состояния требует права `clients.write`, версии и ключа
идемпотентности.

## Последствия

Из старых импортов сделки не создаются. Форма показывает пользователя,
который активировал виджет. Неопределённая отправка может потребовать
проверки в CRM, если сделка ещё не индексирована или название изменили.
