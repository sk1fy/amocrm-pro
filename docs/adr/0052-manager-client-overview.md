# ADR 0052. Сводка списка клиентов в снимке Platform

## Контекст

Карточки сводки фильтруют список клиентов. На следующих страницах
счётчики и строки должны относиться к одному снимку. Текущая авторизация
и свежесть списка пользователей известны Platform. Подтверждённых
наблюдений срока лицензии и пробного периода amoCRM пока нет.

## Решение

Считать разбивку по всем доступным аккаунтам в транзакции первой
страницы и сохранять её вместе с курсорным снимком. Для «Получаем данные»
требуются свежий список пользователей и текущая авторизация в Core.
«Запрет работы» имеет приоритет. Фильтры по группе, классификации,
линейке и способу продления применяются до пагинации.

Сопоставлять текущие виджеты с их линейками каталога. Установленный
виджет без линейки отображается в списке как Trial. Это правило
отображения и фильтра, отдельное от состояния лицензии amoCRM.

Для ручной классификации «Клиент партнёра» сохранять название партнёра
в версионном профиле аккаунта. Название передаёт менеджер с правом
`clients.write`. Связи каталога компаний с аккаунтами не описывают
партнёрские отношения. «Без партнёра» даёт способ «Напрямую»,
партнёрская классификация даёт «Через партнёра».

## Отклонённые варианты

Подсчёт по загруженной странице делает карточки зависимыми от лимита.
Вывод способов продления из сроков требует наблюдений, которых пока
нет, и не даёт менеджеру явно классифицировать аккаунт.

## Последствия

Новые поля в API опциональны. Для обновления рабочего стека сначала
нужен новый Admin BFF, который строго проверяет схему Platform, затем
миграция и новая Platform. Миграция вниз останавливается при сохранённых
партнёрских назначениях.
