# ADR 0040: Регистрация MVP «Контроля активности 2.0»

Дата: 2026-10-27. Статус: принято для MVP.

## Контекст

Панель аналитики и виджет сотрудников используют один продукт Activity.
Core уже хранит интеграции amoCRM, OAuth-установки и grant `activity`.
Нужна однозначная регистрация MVP и видимость его подключения в админке.

## Решение

Переиспользуем capability `activity`, текущие API и таблицы.
Новый сервис и регистрация клиентских credentials миграцией не нужны.
Код интеграции Core и код пакета виджета могут различаться;
установка определяется проверенной парой `client_uuid + account_id`.

Связь продукта: grant `activity` → integration ID/code/client ID →
installation ID/account ID. Client ID — UUID интеграции amoCRM;
это не внутренний integration ID Core. Секрет остаётся на сервере.

Админка определяет название продукта по наличию grant, включая
выключенный grant. Статусы интеграции, установки, OAuth, grant
и pilot независимы. Отсутствие наблюдения не означает выключение.

Сотрудник с действующим JWT и актуальным признаком active получает
доступ к своим сессиям. Управление требует текущей роли администратора.
Capability и installation pilot обязательны обоим.

## Отклонённые варианты

Новая capability `activity-v2` дублировала бы права и настройки.
Привязка по имени пакета вместо проверенного UUID нарушает
изоляцию интеграций в одном аккаунте.

## Последствия

Подключение использует существующие audited provisioning и OAuth.
Живой OAuth и SDK проверяются отдельно от синтетических тестов.
Подготовка ZIP и развёртывание относятся к КА-01.04.
Приёмка: [инструкция](../runbooks/activity-mvp-registration.md).
