# Две проверки лимита подписки

## Контекст

[ADR-0058](0058-account-subscriptions.md) определяет пакет и его
влияние на доступ. Первое наблюдение сверх лимита должно показывать
предупреждение. Для приостановки нужны два наблюдения подряд.

## Решение

Platform хранит два последних завершённых обновления пользователей для
аккаунта. Плановый и ручной запуск используют общую очередь обновления.
Снимок, запрошенный для подготовки сделки, обновляет карточку отдельно.
Повторное, просроченное или неуспешное наблюдение не продвигает проверку.

Выдача пакета, изменение лимита и продление истёкшего пакета задают
новую точку отсчёта. Для действующего пакета с прежним лимитом сохраняются
обе проверки. При переходе на новую схему старый снимок даёт одну проверку.

Platform нумерует принятые проверки отдельно по каждому аккаунту. Команда
смены лимита сохраняет последний номер под блокировкой той же строки,
которую обновляет новая проверка. Сравнение номеров исключает влияние
расхождения часов Core и PostgreSQL. Время наблюдения используется для
отсечения повторов и устаревших снимков.

## Последствия

Пакет активен при первом превышении и возвращает seats_warning.
Второе превышение делает пакет suspended. Проверка в пределах лимита
возобновляет неистёкший пакет. Собственный доступ виджета остаётся
в общем расчёте при любом результате.
