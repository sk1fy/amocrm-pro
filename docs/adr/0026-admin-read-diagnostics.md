# ADR-0026: согласованные факты диагностики в admin read API

- **Status:** Accepted.
- **Date:** 2026-09-13.

Дополняет [ADR-0025](0025-admin-read-listener.md) по результатам проверки
первого этапа админ-панели.

## Контекст

Список аккаунтов передавал число недавних ошибок jobs, а карточки того же
аккаунта и установки — нет. Фильтр продукта в админке не мог использовать
гранты сервиса, поскольку краткие установки списка их не содержали. Новый
просмотр доставок наследовал порядок CLI и при лимите показывал старые
команды вместо последних. Публичный dev-токен Compose принимался и вне
development.

## Решение

- Каждая установка в списке аккаунтов содержит `grants` в существующем
  формате `{service, enabled}`. Гранты читаются одним запросом по интеграциям
  выбранной страницы; отсутствующие гранты представлены пустым массивом.
- `recent_failed_jobs` присутствует в списках и карточках аккаунтов и
  установок. Один SQL-фрагмент считает `failed`/`dead` с
  `updated_at > now() - interval '24 hours'`; отсутствие ошибок — число `0`.
- Admin HTTP возвращает доставки по `receipt.created_at DESC,
  command_id DESC`. `ListDeliveries` для CLI сохраняет прежний фильтр
  failed/expired и порядок от старых к новым; новый порядок выбирается
  явно через `DeliveryFilter.NewestFirst`.
- Core отвергает публичный dev-токен админки при любом `APP_ENV`, кроме
  `development`, аналогично уже существующей защите dev-ключа шифрования.

## Последствия

Изменения JSON обратно совместимы: добавлены факты, существующие поля не
переименованы. Таблицы и миграции не меняются. Публичный API, мутации worker
и порядок CLI не меняются. Неполная production-конфигурация с публичным
dev-токеном теперь останавливает запуск до открытия listener.

Контракт: `api/admin-openapi.yaml`; HTTP integration-тесты проверяют JSON
по схеме, согласованность счётчиков, гранты и отдельный порядок CLI.
