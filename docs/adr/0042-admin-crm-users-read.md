# ADR 0042: Пользователи amoCRM для админки через worker

Дата: 2026-11-06. Статус: принято.

## Контекст

Карточке аккаунта в админке нужен список пользователей amoCRM: ID, имя,
признаки активности и администратора. В Core пользователей уже читает
`amocrm.Client.CRMUsers`: справочники TeamOS (`crmreferences`) и
распределение. Эти чтения выполняет worker — единственный владелец
исходящего трафика amoCRM, OAuth-провайдера и бюджета (ADR-0019,
ADR-0029). Admin listener процесса `api` (ADR-0025) читает только
PostgreSQL Core и в amoCRM не ходит. Сохранять список пользователей
в Core незачем: это персональные данные, а не факт, которым владеет Core.

## Решение

1. Новый необязательный listener worker `ADMIN_CRM_HTTP_ADDRESS`
   (`:8085`, сеть `amocrm-admin-link`, alias `core-admin-crm`).
   Токен — общий `ADMIN_API_TOKEN` admin listener; адрес без токена — ошибка
   старта; публичный dev-токен запрещён вне `APP_ENV=development`.
   Аутентификация и `X-Admin-Actor` — те же, что у admin listener
   (`adminread.Authenticate`); actor попадает только в access log.
2. Маршрут `GET /admin/v1/accounts/{account_id}/crm-users`
   (`apicontract.AdminCRMRoutes`, описан в `api/admin-openapi.yaml`).
   Пакет `internal/admincrm` выбирает активную установку активной
   интеграции с сохранёнными OAuth credentials, без `origin=fixture`, с
   самыми свежими credentials. Затем вызывает `CRMUsers`: не больше
   четырёх страниц по 250 пользователей, иначе `incomplete`.
3. Проекция: `id`, `name`, `is_active`, `is_admin`. Email, телефон,
   группа, роль и права наружу не выходят.
4. Полный снимок хранится в памяти процесса 5 минут, как снимки
   справочников TeamOS. Ограничение — 256 аккаунтов, одновременные
   запросы объединяются через singleflight. Ошибки не кэшируются.
   Установка, через которую читается аккаунт, определяется при каждом
   запросе, поэтому снимок отозванной или сменённой установки не
   отдаётся.
5. Отказ amoCRM — это наблюдение, а не ошибка listener: `200` с
   `state` = `auth_error`, `rate_limited` (+ `retry_after_seconds`),
   `incomplete`, `network_error`, `internal_error`. Если читать не через
   что — `no_authorized_connection`. Во всех этих состояниях `items` и
   `total` равны `null`: список неизвестен, а не пуст. Аккаунт без
   установок — `404`.

## Отклонённые варианты

- Чтение amoCRM из admin listener процесса `api`: второй владелец
  исходящего трафика и бюджета, нарушение ADR-0019.
- Команда через очередь и снимок в таблице Core: персональные данные в БД
  и в журнале команд, миграция и retention ради справочного чтения.
- Переиспользовать `crmreferences.Provider` как есть: снимок требует
  воронок и групп, лишних для списка, и не содержит признак
  администратора.

## Последствия

GET админки может вызвать до четырёх запросов amoCRM на аккаунт за пять
минут. Они проходят общий бюджет пары и аккаунта. Ответ 401 от amoCRM,
как и при любом другом чтении, может перевести установку в
`reauth_required` через OAuth-провайдер. Кэш процесса не переживает
перезапуск worker и не делится между репликами (worker не
масштабируется, ADR-0029). Email и телефон пользователей требуют
отдельного решения об источнике и доступе.
