# ADR-0035: диагностика и восстановление распределения через Core admin

Дата: 2026-10-03. Статус: принято для локальной реализации РС-09.

## Контекст

Распределение требует диагностики частично доступных owner сервисов и
восстановления без повторного неопределённого CRM эффекта.

## Решение

Core admin listener предоставляет `distribution-read` и
`distribution-commands`: сводку установки, ограниченную цепочку безопасных
идентификаторов и команды через существующие durable admin receipts.
Admin API не подключается к чужим БД. Бизнес-очередь TeamOS не наблюдается этим
контрактом: `team_queue_state=unknown`, счётчики Core означают операции и
доставку Core, а не очередь сделок компании.

Чтение выбирает только безопасные поля и не возвращает frozen payload,
CRM snapshot, credentials и signature material. Поиск принимает UUID,
применяет scope установки ко всем веткам цепочки, использует keyset и лимит
25–100. `message_id` отдельный от уникального диагностического `id` результата.
Нельзя передавать `operationUUID:version` как delivery message UUID.

Проверка подключения и восстановление подписки используют существующие
`check`/`reconcile`. Повтор доставки переводит только blocked сообщение с
совпадающими установкой, UUID и attempts; frozen envelope остаётся прежним.
Сброс attempts начинает новый ограниченный цикл; число предыдущих попыток
остаётся в результате receipt. Уже acknowledged или delivering сообщение
не разрешает эту команду.

`distribution-reconcile` сохраняет admin receipt и отдельный job до внешнего
I/O. Worker читает CRM и вызывает существующий owner `ReconcileAction` с
предусловием версии и идентичным ключом receipt. Он никогда не вызывает PATCH.
Завершение команды наблюдения не означает успешное назначение: состояние
`outcome_unknown` и guard сохраняются без подтверждённого ACK+свежего GET.
Ошибка worker оставляет receipt `unknown_outcome`, а не выдуманный успех.

## Последствия

Новые distribution-команды привязывают semantic hash к admin actor;
повтор ключа другим актором отклоняется. Старые команды сохраняют контракт.
Аудит admission/result остаётся атомарным в admincommand и owner services.

Миграция 21 вводит pause строки всех установок и trigger создания новых.
Пауза применяется только к новой assignment admission, последнему dispatch
и подтверждённому business turn без PATCH. Она не выключает чтение,
нормализацию принятых событий, delivery или проверку уже неизвестного эффекта;
не изменяет TeamOS rules. SQL locks сериализуют pause с новым dispatch.
Запрос, уже прошедший dispatch gate, может завершиться после паузы: guard и
доказательства сохраняются. Откат с paused установками запрещён до явного resume.
