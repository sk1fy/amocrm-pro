# 0062. Тариф amoCRM из виджета

## Контекст

Для первой установки Platform планирует сделку. Введение телефона
может ускорить задачу. Проверенные на техническом аккаунте маршруты
amoCRM с серверным OAuth не возвращали идентификатор тарифа, тип оплаты
и дату окончания пробного периода.

Виджет видит эти поля в `APP.constant('account')`. Он может передать их
при запуске независимо от формы активации.

## Решение

- Core принимает ограниченный набор полей через защищённый маршрут
  виджета и определяет аккаунт по проверенному контексту установки.
  Метку времени приёма назначает Core.
- Platform принимает наблюдение по приватному каналу и проверяет
  актуальные поколение установки и последовательность авторизации.
- Тариф `22000000` используется для определения технического аккаунта
  и блокирует первую сделку. Когда последний принятый тариф становится
  техническим, Platform выставляет «Запрет работы» и записывает прежнюю
  классификацию, имя партнёра и наблюдение виджета. Следующий обычный
  тариф восстанавливает прежний профиль, пока действует этот запрет.
- Явная правка менеджера получает приоритет до конца технического
  периода. При ручном подтверждении запрета Platform записывает
  исполнителя и новую версию профиля. Повтор тарифа сохраняет выбор
  менеджера, а правило первой сделки по техническому тарифу продолжает
  действовать.
- Версия профиля связывает автоматическую блокировку с её событием.
  `account_classification_changes` объединяет изменения виджетом, по
  подписке и вручную. Автоматический аудит хранится отдельно, поскольку
  его основание — наблюдение установки, а ручное изменение требует
  команды с исполнителем. Выдача и продление TOP меняют статус на «Наш
  клиент» для аккаунтов без запрета и технического тарифа.
- При строгой проверке Platform ждёт хотя бы одного пригодного
  наблюдения тарифа. Неполученный тариф отображается в очереди
  установок. Решение о запуске строгой проверки принимается после
  проверки охвата виджетов.

## Последствия

Проверенный токен привязывает сообщение к аккаунту и установке.
Значения полей остаются наблюдением браузера. Они подходят для
маршрутизации работы менеджеров и не используются для выдачи доступа,
назначения ролей или подтверждения оплаты.

Platform использует сохранённую Unix-дату при действующем `pay_type=trial`.
После любого другого `pay_type` нужна дата из нового наблюдения. Состояние
меняется на `expired_pending` на границе даты по времени PostgreSQL.

Отсутствие оплаты подтверждает `pay_type=blocked` или HTTP 402 от запроса
идентичности amoCRM с актуальными OAuth-полномочиями. Platform сохраняет
время ответа 402 в слоте идентичности. Более поздний успешный ответ
идентичности снимает этот сигнал. Ошибки авторизации и сети относятся
к проверке доступа.

Оплату подтверждает успешное наблюдение amoSTART возрастом менее суток.
Оно должно следовать за актуальными признаками пробного периода и
блокировки. Оплаченный срок включает последний день по Москве и должен
выходить за границу действующего пробного периода. Повтор того же значения
обновляет время наблюдения. Для проверки оплаты Platform использует время
изменения значения, в том числе после смены типа оплаты.
