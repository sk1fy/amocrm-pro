# ADR-0015: представления Activity, классификация и покрытие периода

Статус: принято для этапа 4. Дата: 2026-09-08.

Дополняет [ADR-0013](0013-event-detail-read-contract.md) и
[ADR-0014](0014-event-enrichment-contract.md).

## Решение

Пользовательские представления остаются на существующей панели и detail URL.
Новые HTTP endpoints не вводятся. Activity владеет классификацией, русскими
подписями и разделением покрытия/свежести. CRM Events считает сводки, категории
и корзины за весь запрос, не по странице. История B/A не переписывается.

Одиннадцать категорий BASE-03 — единственная таксономия первой версии:
`tasks`, `calls`, `notes`, `messages`, `status`, `budget`, `responsible`,
`custom_fields`, `relations`, `attachments`, `other`. Семейства ACT-02 не
становятся вторым слоем. Исходный `type` сохраняется. Динамические
`custom_field_{id}_value_changed` и суффиксы `_linked`/`_unlinked` входят в
свои категории. Неизвестный тип — `other` и нейтральная подпись «Событие {type}».

Правила интерпретации имеют `interpretation_version=1`. Агрегаты считаются
живой выборкой, сохранённые таблицы агрегатов не вводятся.

## Чтение

`GET /api/v1/widget/activity/panel` добавляет:

| Поле | Смысл |
| --- | --- |
| `categories` | До 11 известных семейств, AND к types/prefix/entity |
| `include_unknown_authors` | `created_by=0` и авторы вне текущего directory |
| `group_id` | Текущий отдел directory; историческое членство не обещается |
| `buckets` | `hour`/`day`/`auto`; час ограничен 48 корзинами |

Пустой `user_ids` по-прежнему берёт directory и дополнительно включает
неизвестных авторов. Неизвестные авторы — `created_by=0` и ID вне текущего
directory; пустой список directory не превращает флаг в «все авторы».
Фильтр отдела сбрасывает этот флаг. Пустое пересечение отдела и сотрудников
не читает всю историю.

При явных `user_ids` вместе с `include_unknown_authors` Activity получает
полный доступный directory одним ограниченным Gateway-вызовом. Все известные
ID используются для исключения действующих невыбранных авторов; отображаемые
сотрудники фильтруются отдельно. Лимит directory в 100 сотрудников сохраняется:
если полный набор не помещается, запрос завершается ошибкой, а не использует
неполный список для определения неизвестных авторов. Явный выбор без unknown
по-прежнему запрашивает только выбранных сотрудников.

Сводка пользователя: число событий, первое/последнее, уникальные сущности,
события `task_completed` и уникальные завершённые задачи, счётчики категорий.
Итоги `data.totals` и журнал используют тот же WHERE. Нулевые сотрудники
directory остаются в `users`.

Журнал получает `view`: category, title, summary, author/entity labels,
`detail_state`. Карточка `GET .../events/{id}` проходит Activity, если порт
доступен, и добавляет details из B/A и enrichment с `source`/`current`.
CRM-тексты — обычные строки, не HTML.
Имена сущностей сопоставляются по kind=entity и нормализованной паре тип/ID
(`lead` = `leads` и т. п.). Совпадение ID контакта и сделки не смешивает имена;
без подходящего имени используется подпись типа и ID.

`read_version=3` у нового owner. Категории, unknown authors и buckets требуют
его; старый peer не игнорирует их молча. Курсоры без новых полей сохраняют
отпечаток v2. Новые опции входят в fingerprint через omitempty.

## Покрытие и свежесть

`coverage` описывает выбранный период: `unknown`/`partial`/`verified`.
Отставание сборщика больше не переводит проверенный завершённый диапазон в
`stale`. `freshness` отдельно: `current`/`lagging`/`error`/`reauth_required`.
Для текущего дня граница — `verified_through`. Пустой проверенный период —
`empty_reason=no_events`. Непроверенный ноль — `unverified_empty`.
Интервал запроса остаётся включительным `[from,to]`.

Корзины времени считаются в timezone аккаунта. Неполная корзина несёт свой
coverage; ноль в ней — зарегистрированный счётчик, не утверждение об отсутствии
истории. Интервал между первым и последним событием не называется сменой.

Начала и окончания корзин формируются в Go как абсолютные Unix timestamps.
SQL использует тот же упорядоченный массив границ и общий WHERE через
`width_bucket`, без обратного преобразования неоднозначного локального часа.
Повторяющиеся осенние часы остаются разными корзинами; дневная корзина может
длиться 23 или 25 часов. `auto` выбирает hour только при фактическом числе
корзин ≤48, иначе day (≤31), включая частичные крайние корзины.

## Выпуск

Согласованно обновить Gateway не требуется. Обновить Activity, CRM Events и
Core. Старый CRM Events при новых presentation options даёт unavailable.
Старые cursors с новыми опциями начать заново. Owner-миграции этапа 4 нет.
ZIP виджета и product UI реализованы на этапе 5 локально; установка ZIP и пилот — этап 8.
