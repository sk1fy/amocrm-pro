# Каталог продуктов V1

Менеджерский каталог использует UUID и код существующего продукта P03. До
первого успешного POST такой продукт остаётся технической записью. POST с
существующим кодом сохраняет его UUID и утверждённые связи интеграций.
Новый код создаёт продукт с пустым списком связей. Подключение Core-интеграции
выполняется владельцем через проверенный manifest P03.

Для чтения каталога нужны clients.read, для POST, PATCH и чтения receipt
своих команд — catalog.manage. Метрики требуют stats.read.
configuration.manage обслуживает настройки портрета. В запросах каталога
integration_refs содержит полный отсортированный набор текущих UUID
интеграций. Указание другого набора возвращает 422.

Название содержит до 200 символов. Каталог хранит до 20 ссылок с абсолютными
HTTP(S) URL без userinfo. availability описывает состояние карточки.
Выданные права определяются собственной записью срока и текущей
авторизацией установки.

## Подтверждение тарифов

Владелец БД добавляет проверенную версию для конкретного продукта.
Значение evidence ссылается на подтверждённое операционное основание.

    INSERT INTO platform_lifecycle.verified_tariff_versions(product_id, version, evidence)
    VALUES ('00000000-0000-4000-8000-000000000001', 2, 'approved tariff document reference');

Менеджер может выбрать эту версию через tariff_version: 2 либо очистить
выбор через tariff_version: null. Подтверждение другого продукта
не подходит. Сохранение выполняется с обычными command ID, idempotency key
и ожидаемой версией карточки.

## Правила первого срока

Операционная таблица initial_term_policies сохраняется для читателя P04.
Миграция переносит её текущие подтверждения в
verified_trial_policies и product_trial_revisions. Уже выданные сроки
сохраняют собственную версию правила и основание.

Для продукта, добавленного после миграции, владелец подтверждает правило
до выбора менеджером.

    INSERT INTO platform_lifecycle.verified_trial_policies(product_id, version, rule, evidence)
    VALUES ('00000000-0000-4000-8000-000000000001', 1, 'top_90d', 'approved TOP policy reference');

Допустимы free, top_90d, pro_7d и pro_14d. Каждая пара
product/version неизменна после её использования как основания. Выбор
менеджера использует последнее подтверждение нужного правила для точного
продукта. FREE выдаёт десять календарных лет UTC с ограничением дня в
конечном месяце. TOP выдаёт 90 дней. PRO допускает 7 или 14 дней.
Формат каталога FREE — {kind: free, duration_days: null}.
Отключение — {kind: none, duration_days: null}.

Каждая смена выбранного правила добавляет ревизию. none удаляет только
операционный слот будущей выдачи. Отсутствие слота понимает предыдущий
читатель P04. Ранее выданный срок и его доказательство остаются в
platform_lifecycle.terms. Повторная авторизация и переустановка сохраняют
этот срок.

Прямой owner SQL из первоначального runbook применим к техническому
продукту до его принятия в каталог. Для принятого продукта подтверждение
добавляется в verified_trial_policies, затем менеджер выбирает правило.
Проверка в конце транзакции запрещает расхождение операционного слота и
выбранной ревизии. Приложение имеет узкие EXECUTE-права на применение
выбранной ревизии. Owner-подтверждения требуют роли владельца БД.

При ручных транзакциях владелец сначала блокирует строку продукта
FOR UPDATE, затем изменяет основания и связанные строки. Приложение
использует тот же порядок. Добавление связей интеграции защищено внешним
ключом строки продукта.

## Пагинация и операционные счётчики

Курсор списка привязан к сотруднику, версии прав, фильтрам, границе
сортировки и версии каталога. Он действует пять минут. Триггеры PostgreSQL
изменяют общую версию при изменениях продуктов, связей интеграций,
операционного правила или истории правил, включая owner SQL.
Изменённый каталог возвращает invalid_cursor. Повтор начинается
без курсора. Сортировка — код и UUID продукта.

confirmed_installations считает подтверждённые поколения установки.
Новая установка и переустановка добавляют эпизод. Повторная авторизация
сохраняет эпизод. При наличии from/to учитывается дата начала эпизода
в PLATFORM_MANAGER_TIME_ZONE, граница to включена как календарный день.

active_accesses — текущее число точных пар account/product с
подтверждённой действующей авторизацией и неистёкшим собственным сроком.
Оно использует проекцию P04 и один момент времени PostgreSQL.
Исторический диапазон не ограничивает текущий счётчик. Истёкший срок
проверяется во время запроса. Для activations подтверждённый источник
G03 пока отсутствует, поэтому в этом контуре результат равен нулю.

## Проверка и откат

make platform-test запускает PostgreSQL, миграции, роли и проверку
TestPlatformProductsAcrossReplicas на реальном mTLS. Проверка охватывает
две реплики, новые и принятые продукты, owner-подтверждения, права,
сохранение и повторы после рестарта, прежние сроки и выключение будущей
выдачи.

Откат миграции P08 блокируется при заполненном каталоге, командах P08 или
новых owner-доказательствах. Guard блокирует таблицы до проверки.
Сначала сохраняют и явно сверяют эти данные с целевой версией.
Пустой P08 можно откатить штатным migrator.
