# ПВ-04: инженерный кандидат и условия пилота

ПВ-04 выполняется параллельно ПВ-03. Изменения продукта изолированы от моста:
`internal/colorleads`, кандидат SQL-схемы внутри пакета, локальный инструмент
`scripts/color-leads`. Подключение в `cmd/api`, номер миграции и изменения SSD
здесь не выполняются.

## Текущая проверяемая часть

- [Инвентарь](../specs/color-leads-pv04-inventory.md): функции и данные по коду,
  особенности правил, самостоятельные эффекты старой вкладки.
- HTTP-контракты, tenant isolation, атомарное потребление JWT и revision CAS.
- Импорт в пустое поколение продукта, повтор команды, запрет перезаписи и
  смены исходного архива; без admission guard доступ закрыт.
- [Подготовка и сверка](../../scripts/color-leads/README.md) локальных снимков.
- Frontend на фикстурах в `rakurs-widgets-new/rkrs_color_leads`: lifecycle,
  readonly при потере маршрута, остановка late callbacks.

Это не подтверждает production baseline, метрики, объём данных, Gateway,
права реального аккаунта или live cutover. Доступ amotehrkrs подтверждён,
но живая/визуальная приёмка отложена пользователем. Указанный в задачах
demorkrs не подменяется другим аккаунтом автоматически.

## Контракт подключения к ПВ-03

1. Зарегистрировать `rkrs_color_leads` и явную связь installation/product/service.
   Согласовать origin/CORS expectation headers, schema migration и
   `widgetauth.VerificationMiddleware`; JWT потребляется внутри product tx.
2. Реализовать Guard с блокировками route/installation, проверкой Core owner,
   active phase, epoch/generation, оплаты и пользовательских прав до commit.
   Сверить порядок блокировок с transfer commands. Заголовки браузера —
   ожидания, не полномочия.
3. Реализовать ImportGuard: подтверждённый transfer, frozen source, достоверные
   drain evidence, отсутствие неизвестных результатов, связь account/install
   и архив экспорта. Хэш архива не заменяет receipt остановки.
4. Подключить типизированные CRM-чтения leads/custom fields/users через Gateway
   и выделенный бюджет аккаунта. Production URL не подставляется наугад.
5. Реализовать обратный импорт и повторный перенос. Текущая команда принимает
   только пустой документ и не перезаписывает изменённый продукт.

## Перед активацией

Общий ZIP не распространяется на всех SSD-пользователей без безопасного
протокола. Отдельная интеграция изолирует распространение, но сама по себе
не исключает старый экземпляр на том же аккаунте.

| Условие | Доказательство |
| --- | --- |
| Подтверждён source | Опубликованный ZIP/hash, integration ID, схема БД, объёмы и метрики |
| Старый writer остановлен | Durable fence, drain/unknown resolution, блокировка всех входов |
| Старые вкладки остановлены | Cleanup observers/listeners/timers, отменённые чтения, late-response guard, блокировка install/account/payment callbacks |
| Цель готова | Mapping, доступ, settings/colors, исходный архив, сопоставление правил |
| Единственный владелец | Commit ПВ-03; до него target не исполняется |
| Возврат готов | Актуальные данные Core перенесены обратно после его остановки и сверены; новый transfer/epoch |

Баннер перезагрузки и localStorage snapshot не доказывают остановку старого
клиента. Если старый код не контролируется, активация Core закрыта до отдельного
доказанного протокола. ПВ-04.05 проверяет старую открытую вкладку и обновление
ZIP. ПВ-04.07 начинается после принятого пилота и возврата, по выбранным
аккаунтам и метрикам, без автоматического массового переключения.
