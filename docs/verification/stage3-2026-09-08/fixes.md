# Исправления ревью этапа 3

Дата: 8 сентября 2026 года. Проверяется рабочее дерево с изменениями этапов
1–3 поверх `8c36827ef041561d2b2d734e5c686f36869812f8`. Runtime и production
не менялись.

## Исправленные дефекты

1. `ClaimEnrichment` повторно выбирает текущие ready-объекты и временные
   отрицательные результаты после `run_after`. TTL: notes/tasks — 15 минут,
   справочники/имена — 5 минут, not_found — 15 минут, permission_denied — час.
   В новом цикле попытки сбрасываются, внутри retry сохраняются.
2. Готовые исторические sidecar строятся из B/A конкретного события при
   GetEvent. Общая таблица объектов больше не получает event_payload.
   Два события одного примечания не разделяют исторический текст; событие
   со ссылкой получает отдельно помеченное текущее состояние Notes API.
3. Убрана замена больших payload на `{"current":true}`. Справочники,
   исходные поля и производные факты сохраняются целиком. Owner-лимит
   объекта — 1 MiB; превышение возвращается как error/invalid без payload.
   Лимиты внешних params/text и общего detail-ответа сохранены.

Новая миграция `000005_enrichment_refresh` расширяет индекс очереди и
перепланирует старые общие event_payload и усечённые заглушки. Исторические
данные берутся из неизменённых crm_events. Down возвращает прежний индекс,
но не восстанавливает сброшенный кеш. Миграция 000004 не переписывалась.

## Проверки

Исходные три дефекта воспроизведены отдельными тестами до исправления:
[три ожидаемых FAIL](fixes/review-failures.txt).

После исправлений прошёл пакет CRM Events с PostgreSQL и `-race`:
[результат](fixes/owner-tests.txt). Дополнительно прошли пять новых
регрессионных тестов вместе с существующими enrichment-тестами:
[результат](fixes/regression.txt).

Новые тесты проверяют восстановление после 403/404 и отсутствие раннего
повтора, изоляцию двух исторических текстов от текущего примечания,
обновление имени после TTL, сохранность 400 полей через БД/GetEvent,
явное состояние при превышении лимита, down/up миграции с повреждённым
кешем и сохранность params вместе с facts около внешнего лимита 32 KiB.

Полный итоговый gate на окончательном коде:

```sh
make COMPOSE=docker-compose ACTIVITY_TEST_PROJECT=amocrm-stage3-fixes-test activity-ci
```

Exit 0; 158 верхнеуровневых Go PASS с `-race`, 3 штатных helper SKIP;
UI 5 PASS, 0 SKIP. Проверены owner PostgreSQL, mTLS, реальные процессы,
аварийные перезапуски, embedded/gRPC и общий бюджет. Необязательный прогон
с предыдущим API-бинарём пропущен: `COMPONENT_PROCESS_PREVIOUS_API_BINARY`
не задан. Тестовые контейнеры и volumes полного gate удалены штатным cleanup.

Артефакты: [Go](fixes/activity-go.txt), [UI](fixes/activity-ui.txt),
[Make/Compose](fixes/activity-ci.txt), [SHA-256 исходников](fixes/source-manifest.json).
`git diff --check` — PASS. Логи регрессионного прогона выше предшествуют
упрощению SQL до одного общего предиката; окончательная форма проверена
полным gate и соответствует manifest.

## Развёртывание

Применить owner-миграции до `000005_enrichment_refresh` включительно и
обновить CRM Events. Для полного этапа 3 сохраняется согласованное
обновление Gateway/Core/Activity из ADR-0014. В этой проверке не выполнялись
production migration, живой amoCRM, сборка/установка ZIP и приёмка UI карточек.
