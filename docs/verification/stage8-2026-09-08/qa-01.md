# QA-01. Автоматизированные проверки новых сценариев и регрессия

Дата: 11 сентября 2026. Задача этапа 8 плана `docs/plans/2026-09-08-activity-backend-development.md`.

Это инвентаризация существующего набора owner/RPC/process/UI tests против чеклиста QA-01 и точечное закрытие реальных пробелов. Четыре копии одинаковых сценариев для MOD-02, REL-01, CORE-07 и QA-01 не писались: используется один набор.

Не production deploy и не полный Docker-gate. Координатор запускает `make activity-ci`, `make integration-test`, `make test`, `make build`.

## Итог

Большинство пунктов чеклиста уже закрыты этапами 2–7. Реальные пробелы относительно **новых публичных чтений** (compact-панель, `EventCard`, owner `GetEvent`/поля enrichment):

1. истёкшая делегация, неверный grant и недоступность Core на этих трёх поверхностях одновременно;
2. одинаковый `resource_exhausted` у `EventCard` и Panel/Query.

Добавлены два focused unit-теста и два расширения существующих deny-тестов. Остальное — «изменение не требуется» с таблицей соответствия.

Запущено (unit, без Docker/PostgreSQL, toolchain хоста):

```sh
gofmt -w internal/services/activity/service_test.go \
  internal/services/activity/stage8_contract_test.go \
  internal/services/crmevents/service_test.go

go test -count=1 -v ./internal/services/activity ./internal/services/crmevents \
  -run 'TestRevocationStopsLocalAdapterBeforeDataAccess|TestUnauthorizedLocalCallsDoNotReachStorage|TestPublicReadsRejectExpiredWrongGrantAndUnavailablePolicy|TestEventCardMapsOversizedResponseLikeQuery'
```

Результат: PASS. Подкейсы `wrong_grant`, `expired_delegation`, `core_unavailable` — PASS.

## Что сознательно не добавлялось

- Повтор round-trip fixture, unknown type, 3 MiB Query, DST, zero employees, enrichment 404/429/5xx — уже есть.
- Process/UI/gRPC parity — границы не менялись.
- Отдельный Postgres-тест «late UPDATE затем Retain»: retention режет по `created_at`, update не подменяет cutoff; восстановление удалённых закрыто `TestSettingsSnapshotOnQueuedAndRunningJobs`.
- HTTP-обёртка compact/`GET /events/{id}` для expired JWT: widget JWT и Issue живут в Core; делегация проверяется в Activity/Events. Публичный путь выдаёт грант `panel` через `UserGrantsFor`; неверный grant на Issue закрыт тем же новым тестом.
