# AMO-1427: завершённый sync блокирует установку

## Объём

База: `amocrm-pro/main`, `68cd134`, сверено 2026-09-19.
Активных patch-планов в `amocrm-pro-admin/docs/plan/README.md` нет;
эта задача ограничена Core и оформлена отдельным patch-планом здесь.

Фактический код: `Store.Execute` проверяет сохранённое состояние под
`admin-key` и `admin-target`; `Store.Get` обновляет Activity sync через
`refreshActivitySync`. Миграция `000016` дополнительно запрещает несколько
незавершённых квитанций одного объекта уникальным частичным индексом.
Маршруты admin, CLI integrations/activity-control и serviceapi не меняются.

- Перед транзакцией приёма обновить pending/running activity-sync объекта
  через существующий bridge; повторно проверить занятость под lock.
- Проверить terminal/running, недоступность источника, идемпотентность,
  конкуренцию и HTTP 202 без предварительного GET.
- Добавить ADR и уточнить lifecycle в runbook.
- Проверки: Docker/Make, регрессия до/после, локальный сценарий на fixtures.
- Интерфейс, новые поля/состояния, retention, публичный API, worker и
  миграции вне объёма; в admin код изменений нет.

## Отчёт

Дата: 2026-09-20. Коммиты: amocrm-pro-admin — без изменений;
amocrm-pro — коммит этого отчёта в `feature/admin-amo-1427-stale-sync`.

### Реализованные экраны и операции

- `Execute` обновляет незавершённые activity-sync до транзакции приёма.
- Терминальный sync освобождает установку без GET; running и
  недоступность источника оставляют конфликт.
- Сохранены advisory locks, повторный EXISTS и идемпотентность.
- Добавлены интеграционные проверки конкуренции разных/одинаковых
  ключей, отсутствия повторного sync/job, HTTP 202 и pool из одного
  соединения. Интерфейс не менялся.

### Изменения контрактов и миграции

- Admin API и Core admin: схемы и маршруты без изменений.
- Миграции admin DB/Core: нет.
- Публичный API и worker: без изменений.
- Lifecycle описан в ADR-0031 и runbook admin-команд.

конкурентные Execute создают ровно один check job; повтор возвращает
прежние ID квитанции/job.

### Инструкция запуска и демонстрационный сценарий

- [Команды админки](../runbooks/admin-commands.md).
- `TestCommandHTTPAfterUnreadActivitySync`: активная fixture-установка,
  pilot → activity-sync → accepted outbox/terminal CRM Events → POST check
  без GET sync-квитанции → HTTP 202.
- `TestExecuteReconcilesUnreadActivitySync`: terminal, running и отказ
  источника; состояние старой квитанции читается напрямую, без
  исправляющего GET, чтобы тест не скрывал регрессию.

### Происхождение данных демонстрации

- Fixture: изолированный PostgreSQL, синтетический bridge и HTTP router.
- Real: не использовались. Общий integration suite и Activity CI работали
  в отдельных Compose-проектах с тестовыми базами.

### Ограничения и зависимости следующего этапа

- Ручной прогон с реальным amoCRM и production rollout не выполнялись.
- При недоступном bridge busy-check остаётся консервативным; подтверждение
  терминального результата требуется до приёма следующей команды.
- UX пустого conflict, retention и настройки Activity вне объёма AMO-1427.
